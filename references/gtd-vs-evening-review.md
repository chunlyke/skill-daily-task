# GTD区 vs 晚间复盘区：职责区分（2026-06-06 实错案例）

## 两个区的定位

| 区域 | 职能 | 内容特征 |
|------|------|---------|
| GTD & Top 5 Tasks | 晨间计划，执行对照 | 保留原始任务名，只改状态标记 |
| 🌙 晚间复盘 | 实际产出记录 | 可包含晨间计划外的额外完成事项 |

## 实错案例（2026-06-06）

**原始GTD区（晨间6月5日写入）：**
```
- [ ] Top1 手机套餐变更
- [ ] Top2 联系杜紫立
- [ ] Top3 联系刘娟
- [ ] Top4 报销
- [ ] Top5 拼多多退货
```

**❌ 错误做法：替换任务**
```
- [x] Top1 P0深蹲破冰   ← 这不是晨间计划的任务！
- [x] Top2 中建一局     ← 也不是！
```

**✅ 正确做法：只改状态，保留原任务名**
```
- [ ] Top1 手机套餐变更 — 🔴 未执行
- [ ] Top2 联系杜紫立 — 🔴 未执行
- [ ] Top3 联系刘娟 — 🔴 未执行
- [x] Top4 报销 — 🟡 发票已转宋远萍处理
- [x] Top5 拼多多退货 — ✅ 已提交退货
```

而P0深蹲破冰、中建一局等实际完成的其他事项 → 放在晚间复盘区的「实际执行记录」中。

## 核心原则

GTD区是**计划档案**——记录"今天早上定了什么目标"。
晚间复盘区是**执行档案**——记录"今天实际干了什么"。
两个数据集不同，不能混为一谈。

## 附加问题：晚间复盘预填的Top 5与GTD晨间计划不匹配

**场景（2026-06-07实错）：** 晨间cron创建日记时，GTD区写入了一套Top 5，晚间复盘区预填了另一套完全不同的Top 5。

**具体数据：**
```
GTD区Top 5（晨间计划）：
  Top1 准备睿睿上学材料
  Top2 联系杜紫立
  Top3 给王俊杰打电话沟通合同问题
  Top4 跟卢国建说部分工资在香港发
  Top5 询问李艾峻父亲的病情

晚间复盘区预填：
  Top1 找卢国建明确项目奖励细节  ← 与GTD不同
  Top2 W24规划                   ← 与GTD不同
  Top3 给王俊杰打电话沟通合同问题  ← 与GTD Top3一致
  Top4 联系杜紫立沟通上学事宜     ← 与GTD Top2一致
  Top5 手机套餐变更               ← 与GTD不同
```

**根因：** cron创建日记时，GTD区写入提案版Top 5，晚间复盘区也用同一提案生成。但如果Kevin在日间通过交互流调整了GTD区（增加/删除/改排序），晚间复盘区不会自动同步——它仍是日记创建时的旧提案。

**晚间确认时的裁决规则（已固化入skill）：**
1. 使用GTD晨间计划作为「今天计划做了什么」的参考源
2. 晚间复盘区的预填内容只作为执行结果的待填充容器，不作为计划参考
3. 晚间确认后，由系统将Kevin确认的执行结果写入晚间复盘区
