# 日记路径探测协议

## 问题背景
Kevin 的 Obsidian 日记库可能存在于两个路径之一：
1. **iCloud 路径** — `/Users/kevin/Library/Mobile Documents/iCloud~md~obsidian/Documents/KevinOB/`
2. **本地 Documents 路径** — `/Users/kevin/Documents/KevinOB/Documents/`

cron 执行时可能因 iCloud 尚未同步完成而找不到文件，直接用本地路径更可靠。

## 文件查找表

| 文件类型 | 路径A（iCloud优先） | 路径B（本地备用） |
|---------|-------------------|-----------------|
| 今日日记 | `~/Library/Mobile Documents/iCloud~md~obsidian/Documents/KevinOB/Dailynote/YYYY-MM-DD.md` | `~/Documents/KevinOB/Documents/Dailynote/YYYY-MM-DD.md` |
| Weekly Review | `…/KevinOB/Dailynote/Weekly Review 2026-WW.md` | `~/Documents/KevinOB/Documents/Weekly Review/Weekly Review 2026-WW.md` |
| Monthly Review | `…/KevinOB/Documents/Monthly Review/…` | `~/Documents/KevinOB/Documents/Monthly Review/…` |

## 首次执行探测流程
```
1. test -f 路径B（本地Documents）→ 存在则使用
2. 不存在 → test -f 路径A（iCloud）
3. 两条都没有 → search_files 跨 /Users/kevin 搜索 "KevinOB" 找任何日记文件定位
4. 确定路径后本会话全部使用该路径
```

## 2026-06-16 实案
cron 22:00 执行时，路径A的日记 `test -f` 返回 NOT_FOUND，路径B的 `test -f` 返回 EXISTS。
Weekly Review 同理：路径A的 WR25 不存在，路径B的 WR25 存在于 `/Users/kevin/Documents/KevinOB/Documents/Weekly Review/`。

## 铁律
- 首次 `test -f` 失败后，不要立即报告"日记不存在"——搜索备用路径
- `search_files` 比 `ls | grep` 更可靠（首次搜索用 `search_files(pattern="*Daily*", target="files", path="~/", limit=10)` 这类）
- 找到后为后续操作使用同一路径，不要混用路径A/B
